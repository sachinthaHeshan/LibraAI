# Responsible AI in LibraAI

How the AI chat (`POST /ai/chat`) and member recommendations are kept safe, private,
transparent, and accountable. Every control below is enforced in code, and the deterministic
ones are covered by tests and by `pnpm eval`.

## Request flow

```
user message
  → JWT auth + organization scope
  → input bounds (≤ 2000 chars, ≤ 40 history messages, last turn must be the user's)
  → sanitize (control / zero-width / bidi-override characters stripped)
  → per-user rate limit (20 messages / minute)            → 429 + audit "rate_limited"
  → deterministic policy on every user turn                → refusal reply + audit "refused"
  → PII masking (emails, phone numbers, card numbers)
  → Mastra orchestrator → specialist agent → org-scoped tools
  → reply + provenance metadata                           → audit "completed" / "failed"
```

A refused request never reaches an LLM or a tool. That holds even when no AI key is configured.

## Controls

| Principle | Control | Code |
|---|---|---|
| Safety | Pattern policy refuses bulk deletion, permission/auth bypass, prompt injection and system-prompt extraction, cross-library access, and bulk export of personal data. Each refusal has a stable code and a plain-language explanation. | `apps/api/src/safety/policy.ts` |
| Safety | Earlier user turns are checked too, so an injection can't be hidden in client-supplied history. The web client drops refused turns from history so one refusal doesn't block the rest of the chat. | `routes/ai-chat.ts`, `apps/web/lib/chat.ts` |
| Safety | Agent prompts tell the model to treat user text and tool output as data, never claim catalog facts a tool didn't return, and never reveal its instructions. These rules back up the code-level policy; they don't replace it. | `mastra/agents/*.ts` |
| Privacy | Emails, phone numbers, and card numbers in user messages are masked before the model sees them. Valid ISBN-10/13 numbers and years are kept. | `redactPii` in `safety/policy.ts` |
| Privacy | Tools return only what the agent needs: `get-my-member` returns membership status and loan count (no name or email), and `borrow-book` no longer returns the member's name. | `mastra/tools/` |
| Fairness | Recommendations are based only on the request, saved preferences, and loan history. The agent is told never to infer or mention age, gender, religion, ethnicity, or other personal traits. | `recommendation-agent.ts` |
| Transparency | Every chat reply carries `meta` (`protocolVersion`, `aiGenerated`, `agents`, `tools`, `refusal`, `piiRedactions`). The UI labels each reply ("AI-generated by Catalog search: searched the catalog…"), explains refusals, and notes when personal details were masked. | `routes/ai-chat.ts`, `components/ChatProvenance.tsx` |
| Transparency | A standing AI disclosure appears under every chat composer. Recommendations are labelled as AI-picked, and Settings has an "AI assistant and your data" section. | `AiDisclosure`, `RecommendedForYou.tsx`, `AiPrivacyNotice.tsx` |
| Accountability | Append-only `ai_audit_events` table: actor, role, outcome, refusal code, agents, tools, SHA-256 digest and length of the input, number of PII redactions, latency. No message text. A database trigger rejects `UPDATE` and `DELETE`. | `safety/audit.ts`, migration `0008` |
| Accountability | Owners can review their library's events with `GET /ai/audit-events?limit=50` (owner-only, org-scoped). | `routes/ai-chat.ts` |
| Abuse prevention | Sliding-window rate limit per organization and user. The limiter is in memory, so each API process enforces it separately. | `safety/rate-limit.ts` |
| Evaluation | `safety.v1.json` covers each refusal category plus benign look-alikes; `pnpm eval` reports precision, recall, and F1 for the production policy. | `apps/api/src/eval/` |

## Refusal codes

| Code | Declines |
|---|---|
| `destructive_action` | Deleting, wiping, or dropping records in bulk |
| `auth_bypass` | Bypassing sign-in or permissions, self-promotion to admin, prompt injection, revealing hidden instructions, jailbreaks |
| `cross_tenant` | Data from other libraries or organizations |
| `bulk_pii_export` | Exporting members' personal or contact details |

## Known limitations

- The policy is pattern-based. It is predictable and testable, but a paraphrased attack can slip past it. The agent-prompt rules and org-scoped tools are the second line of defence.
- Chat history still comes from the browser. Earlier user turns are policy-checked, but assistant turns can be forged. Server-owned conversation history (remediation plan §2) would close this gap.
- Mastra observability traces (`MastraStorageExporter`) store full agent inputs and outputs for debugging in Studio. Restrict access to that storage, or turn the exporter off in production if prompts must not be kept.
- PII masking covers emails, phone numbers, and card numbers, not names or street addresses.
- Rate limits reset when the process restarts and aren't shared across replicas.
